# PostgresBackup — 系統規格書 (Spec)

狀態: `ready-for-agent`

## Problem Statement

資料庫管理員與開發人員在維護 PostgreSQL 時，經常需要對特定資料庫、綱要（Schema）或資料表進行備份與還原。然而現有工作流程存在諸多痛點：
1. **指令複雜且易錯**：手動組合 `pg_dump` 與 `pg_restore` 繁複的參數容易疏漏，若指令參數錯誤可能導致備份不完整或還原非預期的物件。
2. **災難性還原風險**：缺乏防護機制的還原作業可能直接覆蓋營運中資料庫，且在執行前沒有自動備份機制可供倒滅回復。
3. **客戶端工具相容性障礙**：PostgreSQL 官方要求 `pg_dump` 版本必須大於或等於資料庫伺服器版本。使用者常因本機未安裝或版本過舊而遭遇轉儲失敗，且缺乏清楚的工具偵測與安裝引導。
4. **缺乏直覺的歷程管理**：手動備份檔案分散在檔案系統各處，缺乏結構化的歷史紀錄追蹤備份時間、檔案大小、耗時與所用參數。
5. **需要圖形化兼具自動化能力**：既需要現代直覺的桌面介面方便日常手動操作，也需要具備完整日誌輸出的 CLI 工具以便整合自動化腳本。

## Solution

開發一套具備現代化 WPF 桌面使用者介面與完整功能 CLI 的 .NET 10 應用程式 **PostgresBackup**。
- **官方工具核心**：全面回歸 PostgreSQL 官方 `pg_dump`、`pg_restore` 與 `psql` 工具，確保資料一致性與零資安疑慮。
- **環境自動偵測與安裝指南**：啟動時自動掃描本機環境（指定路徑、PATH、常見安裝路徑、Windows Registry），即時比對伺服器版本，並提供內建的官方安裝引導。
- **還原安全防禦機制**：還原前預設強制觸發「還原前安全快照（Pre-Restore Snapshot）」，並提供雙重確認機制防止誤操作。
- **安全憑證管理**：資料庫密碼透過 Windows 認證存放機制保護，不以明文儲存於組態檔。
- **歷史倉儲抽離設計**：將歷史紀錄持久化介面獨立抽離為 `IBackupHistoryRepository`，以 SQLite 輕量化持久化每筆操作的完整稽核紀錄。
- **完整 CLI 支援**：支援命令列參數直接執行備份與還原，並具備詳細的標準日誌輸出。

## User Stories

1. 身為資料庫管理員，我希望系統能自動偵測本機是否安裝了官方 `pg_dump` 與 `pg_restore`，以便我了解目前環境是否具備備份還原能力。
2. 身為資料庫管理員，當本機未安裝客戶端工具或版本低於伺服器時，我希望介面顯示警告與官方安裝說明頁面，以便我能快速安裝合規的工具版本。
3. 身為使用者，我希望能自行指定客戶端工具的路徑，以便在便攜式環境或非標準安裝目錄下使用。
4. 身為開發人員，我希望能輸入並測試 PostgreSQL 伺服器連線，以便在執行任何作業前驗證網路端點與驗證資訊。
5. 身為安全意識的使用者，我希望密碼被加密存放在 Windows 認證管理器中，以避免密碼以明文外流。
6. 身為維運人員，我希望能為特定資料庫執行完整備份作業，以便保留資料庫的完整結構與資料。
7. 身為開發人員，我希望能勾選指定的 Schema 或特定的資料表進行備份，以減少不必要的備份檔案大小與時間。
8. 身為資料庫管理員，我希望能選擇自訂二進位格式（Custom, `-Fc`）或純文字腳本（Plain SQL, `-Fp`），以便根據後續還原情境挑選合適格式。
9. 身為維運人員，我希望能選擇僅備份結構（Schema Only）或僅備份資料（Data Only），以滿足開發環境搭建或特定資料轉移需求。
10. 身為使用者，我希望能即時看見備份作業的終端命令輸出與進度日誌，以便了解備份當前的執行階段與預估進展。
11. 身為使用者，我希望能自訂備份檔案存放目錄，且檔案依據 `{database}_{yyyyMMddHHmmss}` 自動規範命名，以便日後歸檔辨識。
12. 身為資料庫管理員，我希望能在還原備份檔案前預覽備份檔案內容標記，以便確認檔案合規性與目標資料庫。
13. 身為維運人員，我希望能選擇還原模式（清除並重建、僅建立遺漏物件、僅寫入資料），以符合不同的復原場景。
14. 身為系統管理員，當我執行還原作業前，我希望系統預設自動先建立一份目標資料庫的「還原前安全快照」，以防止意外資料覆蓋造成不可挽回的災難。
15. 身為使用者，在還原作業正式執行前，我希望能收到高危險警告確認對話框，明確提示即將受影響的資料庫名稱，以避免人為誤操作。
16. 身為使用者，我希望每次備份與還原完成後，系統自動將時間、檔案路徑、檔案大小、執行耗時、操作狀態與完整參數紀錄至歷史清單中，以利日後稽核。
17. 身為使用者，我希望能檢視過往的備份紀錄清單，並可直接從歷史清單中選取特定備份檔案發起還原作業。
18. 身為自動化工程師，我希望透過 CLI 命令列執行備份作業，並能透過 `--log` 參數將詳細日誌輸出至檔案或標準輸出，以便整合至批次任務中。
19. 身為自動化工程師，我希望透過 CLI 命令列執行還原作業，且支援非互動模式與安全快照開關。
20. 身為使用者，我希望享有現代化美觀且流暢的 WPF 介面（基於 HandyControl），具備清晰的視覺識別，帶來愉悅的操作體驗。

## Implementation Decisions

### 1. 模組架構與分層
- **PostgresBackup.Core**：核心類別庫，包含領域模型、`IClientToolRunner`、`ToolDetectionService`、參數構建器、`IBackupHistoryRepository`、SQLite 倉儲實作、連線驗證服務。
- **PostgresBackup.Cli**：命令列進入點，基於 `System.CommandLine` 與 `Microsoft.Extensions.Logging`，直接使用 Core 提供之功能。
- **PostgresBackup.Wpf**：現代化圖形介面，使用 `HandyControl 3.5.1` 與 `CommunityToolkit.Mvvm`，提供直覺的精靈與管理視窗。

### 2. 核心架構接縫（Seams）設計
為確保最高可測性與最低耦合度，定義以下頂層抽象接縫：
- `IClientToolRunner`：封裝外部程序（`pg_dump`、`pg_restore`、`psql`）的呼叫、環境變數傳遞（`PGPASSWORD`）、退出碼驗證與標準輸出/錯誤串流轉發。
- `IToolDetectionService`：封裝環境搜尋與版本解析，提供客戶端工具存在性及版本相容性判斷。
- `IBackupHistoryRepository`：將備份歷史儲存抽離為獨立介面，隔離底層 SQLite 讀寫邏輯。
- `ICredentialStorage`：封裝憑證加解密與儲存，隔離 Windows 憑證存取。

### 3. 客戶端工具偵測管線
- 優先順序：使用者手動指定路徑 → 環境變數 `PATH` → 常見安裝路徑（`C:\Program Files\PostgreSQL\*\bin`）→ Windows Registry（`SOFTWARE\PostgreSQL\Installations`）。
- 版本判定：執行 `<tool> --version` 解析主版本號，並與 Npgsql 連線取出的伺服器版本（`SHOW server_version;`）進行比較。
- 內建指引：提供專屬說明頁面與按鈕，引導前往 EnterpriseDB / PostgreSQL 官方下載頁，並提供 `winget install PostgreSQL.PostgreSQL` 快速安裝命令。

### 4. 備份與還原引擎
- 嚴格使用官方二進位檔，禁止使用非官方解析器。
- 支援格式：Custom (`-Fc`, `.dump`) 為預設，Plain SQL (`-Fp`, `.sql`) 為輔助。
- 參數組合：細緻支援 `--schema-only`、`--data-only`、`-n <schema>`、`-t <table>`、`--clean`、`--create`。
- 還原前安全快照（Pre-Restore Snapshot）：還原流程前自動發起一次 `pg_dump -Fc`，若快照失敗則終止還原。

### 5. 安全與憑證
- 密碼絕不寫入純文字組態檔。
- 密碼透過環境變數傳遞給外部工具處理序，避免出現在命令列參數中造成處理序監控工具洩漏。

## Testing Decisions

1. **外部行為測試**：所有單元測試與整合測試僅測試外部契約與行為，不測試私有內部細節。
2. **命令參數構建測試**：全面測試 `BackupArgumentsBuilder` 與 `RestoreArgumentsBuilder`，驗證特殊字元跳脫、旗標組合、格式指定之正確性。
3. **工具偵測與版本比對測試**：透過虛擬檔案系統或假路徑，驗證主版本高低比較邏輯（例如 pg_dump 15 vs server 16 回傳版本不相容警告）。
4. **歷史倉儲整合測試**：使用 SQLite 記憶體資料庫測試 `IBackupHistoryRepository` 的新增、查詢、過濾與排序行為。
5. **虛擬工具執行測試**：透過 Mock `IClientToolRunner` 模擬程序成功、失敗、錯誤碼與日誌事件，驗證 UI 與 CLI 的狀態響應。

## Out of Scope

1. **跨平台支援**：第一階段專注於 Windows 平台（WPF + Windows Credential Manager）。
2. **內建定時排程服務**：不自建常駐 Windows 服務，定時排程交由 Windows 工作排程器配合 PostgresBackup.Cli 執行。
3. **雲端儲存直接上傳**：本版本專注於本機硬碟與網路共享路徑（NAS/UNC）。
4. **其他資料庫支援**：不支援 MySQL、SQL Server 等其他關聯式資料庫。

## Further Notes

- 本工具為獨立產品，與 `PostgresDeployer` 共享設計理念與品質水準，但在專案結構、配色風格與功能焦點上完全獨立。
- 遵循繁體中文在地化原則，所有 UI 介面與日誌提示皆以繁體中文為預設。
